# Скифы Алтая. Древности Сибири — офлайн-макет киоска

Код структурирован по ТЗ «как есть»: реальный Three.js + GLTFLoader
для 3D-объектов (а не имитация), настоящие пути к видео/картинкам/моделям,
редактируемые отдельно тексты. Ничего лишнего добавлять не нужно —
только положить файлы по указанным путям.

## ⚠️ Важно: как запускать

ES-модули (`<script type="module">`) браузер **не откроет напрямую с
диска** (`file://…`) — сработает защита CORS, приложение останется
чёрным экраном. Нужен любой локальный HTTP-сервер. Проще всего:

```bash
cd skifi-kiosk
python3 -m http.server 8000
```

и открыть `http://localhost:8000/`. Так же будет работать на самом
киоске: либо через `python3 -m http.server`, либо через любой другой
локальный веб-сервер (nginx, `npx serve`, встроенный сервер Windows-
приложения-обёртки и т.п.) — открывать `index.html` двойным кликом
**не получится**.

## Структура проекта (ТЗ п.17)

```
skifi-kiosk/
├── index.html                 — разметка экранов, import map для Three.js
├── css/style.css              — весь визуальный стиль
├── js/
│   ├── app.js                 — управление экранами (video → map → object → authors)
│   ├── data/content.js        — тексты, пути к файлам, координаты меток на карте
│   ├── screens/
│   │   ├── video.js           — заставка
│   │   ├── map.js             — интерактивная карта
│   │   ├── object3d.js        — 3D-стадия (Three.js + GLTFLoader, с заглушкой)
│   │   ├── object2d.js        — 2D-стадия (ковёр: pan/zoom)
│   │   └── authors.js         — экран «Авторы»
│   ├── utils/
│   │   ├── pagination.js      — пагинация текстовых блоков (▰ ▱ ▱)
│   │   ├── hints.js           — подсказки, исчезающие после первого касания
│   │   ├── idle.js            — глобальный таймер простоя (attract loop → возврат к видео)
│   │   └── preload.js         — предзагрузка всех моделей/картинок при старте
│   └── vendor/                — сюда кладётся Three.js, см. vendor/README.md
├── assets/
│   ├── video/    → intro.mp4
│   ├── images/   → map.jpg, carpet.jpg, authors-qr.png
│   ├── models/   → panther.glb, human.glb
│   ├── fonts/    → брендовые шрифты (опционально)
│   └── texts/    → см. texts/README.md (по умолчанию тексты в content.js)
└── README.md
```

В каждой папке `assets/*/README.md` — какой именно файл там ожидается.

## Что уже работает по ТЗ

- **Архитектура** ровно как в схеме: VIDEO → MAP → (PANTHER | HUMAN |
  CARPET) → AUTHORS → QR, с плавными переходами между экранами и
  затемнением (п.8–9).
- **Карта** (п.9) — метки объектов берутся из `content.js`
  (`hotspot: {x, y}` в процентах), при добавлении нового объекта
  достаточно дописать его в `CONTENT.objects`.
- **3D «Пантера»/«Человек»** (п.11–12) — настоящий рендер Three.js:
  сцена, свет, `GLTFLoader`, авто-подгонка размера/центрирование модели
  под сцену. Логика взаимодействия — как описано:
  вращение пальцем → выключает автовращение → 10 сек бездействия →
  сброс положения и возобновление автовращения; удержание пальца без
  движения не считается новым действием; масштаб — pinch двумя
  пальцами.
- **2D «Ковёр»** (п.13) — pan/zoom изображения (палец/мышь + pinch/
  колесо мыши для отладки на десктопе), с ограничением смещения.
  Архитектурно оставлено место под будущие интерактивные зоны
  (увеличение участка → доп. текст) — их можно добавить в `content.js`
  и обработать в `object2d.js`, не переписывая остальное.
- **Текстовые блоки** (п.10) — пагинация `< текст >` + индикатор
  `▰ ▱ ▱` (некликабельный), общий переиспользуемый класс `TextPager`.
- **Подсказки** (п.14) — ненавязчивые, появляются один раз при первом
  открытии экрана/объекта, исчезают после первого касания.
- **Авторы + QR** (п.15) — отдельный экран, `authors-qr.png` подставляется
  как обычная картинка (сгенерировать реальный QR можно любым онлайн-
  генератором один раз на этапе подготовки контента — на самом киоске
  генерация не нужна, это статичное изображение).
- **Стиль** (п.16) — тёмный фон, бронза/золото/пергамент, читаемая
  антиква с small-caps в заголовках.
- **Attract loop** (двухуровневый) — если после видео **не было вообще
  никакого взаимодействия** дольше `FIRST_IDLE_MS` (20 секунд), видео
  запускается заново. Если взаимодействие было хотя бы одно (открыли
  объект, нажали «Авторы» и т.д.) — включается второй таймер,
  `REPEAT_IDLE_MS` (5 минут), который перезапускается при каждом
  следующем взаимодействии; видео возвращается только через 5 минут
  ПОСЛЕ ПОСЛЕДНЕГО касания. Обе константы — в начале `js/app.js`.
- **Ковёр — интерактивная «дырка»** (расширение п.13) — на картинке
  ковра есть подсвеченная метка на месте повреждения. Касание: плавное
  приближение именно к этой точке (кросс-фейд на `carpet-hole-
  restored.jpg` + отдельный текстовый блок про реставрацию), кнопка
  «Ковёр целиком» возвращает к общему виду. Область, где лежит ковёр,
  теперь точно совпадает с фактическими краями картинки (раньше холст
  был искусственно больше самой картинки) — при увеличении
  панорамирование ограничено этими же краями.
- **Метки на карте — два режима** — по умолчанию круглая кнопка с
  эмодзи (как сейчас). Как только появятся готовые картинки-вырезки
  объектов (PNG с прозрачным фоном, точно совмещённые с картой) —
  достаточно добавить в `content.js` у нужного объекта поле
  `hotspotImage` (и не обязательно `hotspotWidth`), и метка сама
  переключится на кликабельную картинку с подсветкой по её реальному
  контуру (не по круглой зоне) — без правок кода. Подробности и пример
  — комментарий прямо над `objects` в `content.js`.
- **Разгон перед переходом** — при касании объекта на карте она на
  ~380 мс притемняется, а выбранный объект подсвечивается сильнее и
  чуть увеличивается, и только потом происходит переход на экран
  объекта — вместо мгновенного жёсткого переключения.
- **Предзагрузка** (`js/utils/preload.js`) — сразу после старта, пока
  крутится видео-заставка, в фоне начинают грузиться и парситься ВСЕ
  `.glb`-модели и прогреваются все картинки. К моменту, когда
  пользователь дойдёт до карты и начнёт открывать объекты, всё уже
  готово — открытие мгновенное, без ожидания. Если предзагрузка ещё не
  успела завершиться (очень медленная сеть) — соответствующий объект
  просто подгрузится как раньше, по требованию.
- **Анимация появления** — модель/картинка объекта плавно проявляется
  (fade + лёгкое увеличение) ровно в момент, когда она реально готова
  к показу — а не в момент открытия экрана. Раньше анимации не было
  вовсе, из-за чего казалось, что объект просто «выскакивает» после
  невидимой задержки загрузки.

## Что делать, чтобы всё заработало «по-настоящему»

1. Положить `three.module.js` и `GLTFLoader.js` в `js/vendor/` —
   инструкция в `js/vendor/README.md`.
2. Положить файлы ассетов по путям из `assets/*/README.md`
   (`intro.mp4`, `map.jpg`, `carpet.jpg`, `carpet-hole-restored.jpg`,
   `authors-qr.png`, `panther.glb`, `human.glb`).
3. При необходимости скорректировать позиции меток на карте
   (`hotspot.x/y` в `js/data/content.js`) под реальную картинку карты.
4. Отредактировать тексты объектов там же, в `content.js`.

**Пока чего-то из этого нет** — соответствующий экран не падает и не
ломает остальной интерфейс, а показывает аккуратную заглушку с прямой
подсказкой, какой файл нужно добавить (текст «Файл не найден:
assets/...» прямо на экране и в консоли браузера).

## Открытые вопросы из ТЗ (п.19) — влияют на доработку макета

- Тип оборудования: Windows ПК + сенсорный монитор / готовый
  интерактивный киоск / Android-панель? (от этого зависит, нужен ли
  дополнительный «обёрточный» лаунчер поверх браузера, автозапуск в
  full screen и блокировка выхода из приложения — сейчас это не
  реализовано).
- Разрешение и диагональ экрана — сейчас вёрстка адаптивная (flex/%),
  но финальную раскладку карты и меток лучше подгонять под конкретное
  разрешение.
- Кто предоставляет финальные 3D-модели, тексты и дизайн карты —
  до получения ассетов макет работает в режиме заглушек, описанном выше.
